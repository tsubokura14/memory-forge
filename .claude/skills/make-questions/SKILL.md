選択式の問題のファイルを、作業場所の `questions/` に作る、または直す。このスキルは、このプロジェクトのもの（`CLAUDE.project.md` の「このプロジェクトのスキル」）。

- ファイルの形・項目・確かめることの全部は `docs/specs/import.md` の「問題のファイル」「ファイルの確かめ」。作る前に読む
- 問題の ID は、スクリプト（`npm run questions:ids`）が付ける。**ID を自分で考えない**
- 作ったファイルを、アプリに取り込まない（取り込みは、人が Import の画面から行う）
- `questions/` の外のファイルを書き換えない。`questions/` のファイルは Git に入らない

## どちらの頼みか

- 新しく作る：`/make-questions Python Decorators 10問` のように、Subject・Topic・問題数を渡された →「作る」
- 直す・足す：「questions/python.json の k3f9a2 の解説を直して」「印の付いた問題を直して」「questions/python.json に問題を5問足して」のように、`questions/` のファイルを示された →「直す」
- どちらか分からなければ、聞く

## 作る

1. Subject・Topic・問題数を確かめる。1つでも足りなければ、作る前に聞く。どんな問題がほしいか（題材、難しさ、単一選択と複数選択の割合など）は、言われたものに合わせ、言われなければ自分で決めてよい
2. 資料（手元のファイルや URL）を渡されたら、読んでから、資料に書いてあることをもとに作る。渡されなければ、知っていることから作る
3. `questions/` がなければ作る
4. ファイルの名前を決める。`<Subject>-<Topic>` に、書き出しのファイル名と同じ決まり（`src/server/manage/export.ts` の `exportFileName`）を当てる：小文字にし、空白と `\ / : * ? " < > |`・制御文字を「-」にし、続く「-」は1つにまとめ、頭と終わりの「-」を除いて `.json` を付ける（例：`Python` と `Decorators` → `python-decorators.json`）
   - 同じ名前のファイルがあれば、上書きしない。名前の終わりに `-2`、`-3`…を付けて、ないものにする（`python-decorators-2.json`）
5. 下の「作り方のルール」に沿って問題を書く。各問題の `id` は `""` にしておく

   ````json
   {
     "subject": "Python",
     "questions": [
       {
         "id": "",
         "topic": "Decorators",
         "type": "single",
         "text": "次のコードを実行したとき、出力されるものはどれか。\n\n```python\nprint(1)\n```",
         "choices": ["1", "None", "エラー", "何も出ない"],
         "correct": ["A"],
         "explanation": "..."
       }
     ]
   }
   ````

   - 項目の並びは `id`・`topic`・`type`・`text`・`choices`・`correct`・`explanation`。決まった項目のほかは書かない
   - `subject` と `topic` は、渡された名前をそのまま書く（前後の空白も比べるので、足さない）
   - 文の改行は JSON の `\n` で書く。2文字の字下げ、終わりに改行
6. `npm run questions:ids -- questions/<ファイル>` で ID を付ける。「〜問に ID を付けました。」と出る
7. 下の「確かめる」を行う
8. 作ったファイルの場所・問題数・Topic を伝える（例：「questions/python-decorators.json に、Python の Decorators の問題を10問作り、確かめました」）。取り込むときは Import の画面でこのファイルを選ぶことを添える

## 直す

`questions/` のファイルは、多くはアプリから書き出したもの（Manage の「<Subject> を書き出す」「<Subject> の不備の印を書き出す」）。問題の元はアプリの中身で、直したファイルを取り込み直すと、同じ ID の問題が置き換わる。

1. 示されたファイルを読み、頼まれた問題を決める（「印の付いた問題を直して」で、不備の印を書き出したファイルなら、ファイルの全部の問題が印の付いた問題）。どの問題か分からなければ聞く
2. 頼まれた問題だけを直す
   - `id` と `subject` は変えない（変えると、取り込み直したときに別の問題になる）
   - 頼まれた問題のほかは、1文字も変えない
   - 直すところが「作り方のルール」に合わないと気づいたら、合わせて直してよい（頼まれた問題の中だけ）
3. 問題を足すように頼まれたら、足す問題の `id` を `""` にして書き、`npm run questions:ids -- questions/<ファイル>` を走らせる。今ある問題の ID は変わらない
4. 下の「確かめる」を行う。頼まれていない問題に誤りが出たら、直さずに伝え、直すかを聞く
5. 問題ごとに、何をどう直したかを伝える（例：「k3f9a2：解説の、`functools.wraps` の説明の誤りを直しました」）。取り込み直すときは Import の画面でこのファイルを選ぶこと、印の付いた問題を置き換えると印と記録がリセットされることを添える

## 確かめる

1. `npm run questions:check -- questions/<ファイル>` を走らせる
   - 誤りがなければ「python-decorators.json：誤りはありません（Python・10問）。」と出て、0 で終わる
   - 誤りがあれば「python-decorators.json：2 件の不備があります。」の下に、誤りごとに「  k3f9a2  correct  選択肢にありません（E）。」（ID・項目・内容）と出て、0 以外で終わる。文言の意味は `docs/specs/import.md` の「ファイルの確かめ」の表。ID の列の `—` はファイル全体、`#3` は ID のない3問目
2. 誤りがあれば直して、1に戻る。誤りがなくなるまで繰り返す
   - `id` の誤り「ほかのファイル（python.json）と ID が重なっています。」は、`questions/` の同じ Subject のほかのファイルと ID が重なっている。この回に自分が足した問題なら、その `id` を `""` にして `npm run questions:ids` を走らせ直す。もとからあった問題（書き出したファイルどうし）なら、ID を変えずに人に伝える
3. 同じ誤りを3回直しても消えないときは、止めて、出た誤りと試したことを伝える

## 作り方のルール

- 単一選択（`single`）は、正解と言えるものが1つだけになるようにする
- 複数選択（`multiple`）は、正解が2つ以上で、問題文に「すべて選べ」と分かるように書く（例：「当てはまるものをすべて選べ。」）
- 選択肢は2〜8つ。`correct` は選択肢の並び順の記号（A・B・C…）で書く
- 間違いの選択肢も、ありそうなもの（よくある思い違い、似た用語など）にする。「すべて正しい」「どれでもない」は使わない
- 解説には、正解の理由と、ほかの選択肢がなぜ違うかを書く
- コードは、問題文・選択肢・解説の中に ``` で囲んで書き、開きに言語の名前を付ける（```python など）。開きと閉じを必ず対にする。文の中の短いコードは `` ` `` で囲む
- 確かでない事実は、問題にしない。資料を渡されたときは、資料に書いてあることから作る
- 問題文・選択肢・解説は、頼まれた言葉で書く。言われなければ日本語。コード・決まった用語・固有名詞はそのまま
