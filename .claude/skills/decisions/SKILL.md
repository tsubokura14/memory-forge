# 人が決めること・AIが決めること

人の判断は、**プロトタイプでの合意**（`/dev-proto`）と **確認とマージ** の2回にまとめる。その間、AIは止まらずに進める。
そのために、決めることを3つに分ける。分ける基準は「あとから変えるのにどれだけかかるか」と「お金・データ・外部に関わるか」。

## 3つの分け方

| 分け方 | 当てはまるもの | 決め方 |
| --- | --- | --- |
| **人が決める** | 下の「人が決めるもの」 | プロトタイプの会話で、AIが推す案と比べた案（良い点・悪い点）を出し、人が選ぶ。答えは仕様ファイルに書く |
| **AIが決めて書く** | 下の「AIが決めてよいもの」 | AIが選び、仕様ファイルの「AIが決めたこと」に、選んだもの・理由・比べた案を1行ずつ書く。仕様ファイルがない `/dev-fix` では、PR の「レビューで見てほしいところ」に書く。人は PR で見る |
| **決めなくてよい** | 開発用の道具の設定（Lint の規則など）、入っているライブラリの使い方、コードの書き方 | AIが決める。書き残さない（理由が要るものは code-notes スキル） |

## 人が決めるもの

あとから変えると大きく作り直すもの、お金・データ・外部に関わるもの。

- 何を作るか：機能、画面、受け入れ条件、やらないこと
- 技術の選択
  - 言語・フレームワーク
  - デプロイ先
  - データベース・データの保存の仕方
  - 認証の仕方・認証のサービス
  - お金のかかる外部サービス（無料の範囲を超えうるものも）
  - 個人情報の置き場所
  - UI の部品ライブラリ、状態管理のライブラリ（見た目や作り全体に広がり、あとから変えにくいため）
  - 下の「AIが決めてよいもの」の条件に合わないライブラリ
- 影響の大きい変更のやり方
  - データの形や保存の仕方を変え、今あるデータの移し替えが要るもの
  - ログイン・権限・お金・個人情報に関わる動き
  - 削除など、取り消せない操作
  - 複数の画面で使う部品や、トークンの値を変える
  - 外部のサービスとのつなぎ方を変える
  - `docs/design.md` の決まりを変える・足す

## AIが決めてよいもの

- ライブラリ：次の **すべて** に当たるもの
  - 無料で、ライセンスが MIT・BSD・Apache-2.0・ISC のどれか
  - 保守されている（最後のリリースが1年以内）
  - 使う場所を1つのモジュール（1つのファイルか1つのフォルダ）に閉じられる。外したくなったら、そこだけ直せばよい
  - データの保存・認証・お金・個人情報・外部への通信に触らない
  - 同じ用途のライブラリが、まだ入っていない
- 設計の選択で、上の「人が決めるもの」に当たらないもの（ファイルの分け方、関数の分け方、テストの書き方など）
- 仕様とスクリーンショットで決まっていない細部で、受け入れ条件を変えないもの（スクリーンショットにない状態の文言、並び順の既定値など）。`docs/ui.md` と今ある画面の書き方に合わせる

入れたライブラリは、code-notes スキルに沿って `docs/libraries/` の下書きも書く。

## 技術の確認表

人が決めるものの漏れを見つけるための表。`/dev-proto` の最後に、仕様ファイルの「技術の確認表」を埋める。

| 項目 | 見ること |
| --- | --- |
| 保存するデータ | 新しく保存するもの、形が変わるもの、移し替えが要るもの |
| 外部サービス | 新しくつなぐもの、つなぎ方が変わるもの |
| 認証・権限 | ログインの要否、誰が何をできるかが変わるか |
| 費用 | お金がかかるもの、無料の範囲を超えうるもの |
| 個人情報 | 新しく扱うもの、置き場所 |
| デプロイの環境 | デプロイ先、環境変数、ビルドの仕方が変わるか |
| 新しいライブラリ | 名前と、「人が決める」「AIが決めて書く」のどちらに当たるか |
| 取り消せない操作 | 削除など |
| 共通の部品・トークン | 複数の画面に効く変更 |
| `docs/design.md` の決まり | 変える・足すもの |

- 当てはまる項目のうち、「人が決める」もので、`docs/overview.md`・`docs/design.md` にまだ決まっていないものは、その会話で人に聞く。答えを仕様ファイルに書いてから合意にする
- 当てはまらない項目は「なし」と書く。空欄にしない（見たかどうかが分からなくなるため）

## 実装の途中で見つかったとき

- 「人が決める」ものが、仕様ファイル・`docs/design.md`・`docs/overview.md` で決まっていないと分かったら、**止まって人に聞く**。プロトタイプでの合意の漏れなので、ここだけは止まる。決まったら、先に仕様ファイル（「技術の確認表」も）を直してから再開する
- 「AIが決めてよい」ものは止まらない。決めて「AIが決めたこと」に書き、進める
- どちらか迷ったら、「人が決める」として扱う
