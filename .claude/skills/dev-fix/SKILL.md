---
name: dev-fix
description: 軽い・中くらいの流れ（小さな変更、バグ修正、整理）を1つのPRで直す（仕様ファイルは作らない）
argument-hint: <Issue番号>
disable-model-invocation: true
---

Issue #$ARGUMENTS を、1つの PR で直す。

1. `gh issue view $ARGUMENTS` で Issue を読む。ラベルで流れを確かめる
   - `flow:light`：軽い流れ。`flow:medium`：中くらいの流れ
   - `flow:heavy` なら、止まって `/dev-spec $ARGUMENTS` を使うよう伝える。流れのラベルがなければ、止まって `/dev-triage $ARGUMENTS` を使うよう伝える
2. 関係する `docs/specs/` を読む
3. 「どうなるべきか」が Issue に書かれていない、または `docs/specs/` と食い違う場合は、**直す前に** 人間に伝えて決めてもらう
4. main を最新にして、`$ARGUMENTS-<英語の短い名前>` ブランチを作る
5. テスト
   - 中くらいの流れ：**バグを再現するテスト、または新しい動きのテストを先に書き、実行して失敗することを確かめる**（実行はサブエージェント `test-runner` に、書いたテストのファイルを渡して頼む）。コミットする。テストを書くかどうかは `docs/process/testing.md` に従う
   - 軽い流れ：新しいテストは書かない。今あるテストが変えた文言などを確かめていれば、一緒に直す
6. 直す。テストが通ったらコミットする。Issue と関係ない所は変えない
   - 原因が、どこにも書かれていなかった前提だった場合は、その前提を書く。直した場所だけに関わるならコメント、複数の場所に関わるなら `docs/design.md`
   - 途中で、`docs/process/flow.md` の「必ず重い流れにするもの」に当たった、または Issue のラベルより大きな変更が要るとわかったら、**止まって伝える**。流れを軽くする方向には、自分で変えない
7. 画面を変えたなら、変えた画面だけを撮り直してコミットする（`docs/process/screenshots.md`）
   - そのあと、サブエージェント `test-runner` に「全部」を渡し、テスト・Lint・型チェック・画像を比べるテストがすべて通ることを確かめる。失敗したら直して、もう一度頼む
   - 画面を変えるつもりがないのに、または変えた画面以外で、画像を比べるテストが失敗したら、撮り直さずに止まり、どの画面がどう変わったかを伝える
8. 動きや文言が変わったなら、`docs/specs/` も同じブランチで直す（仕様のほうが間違っていたと決まった場合も）
9. 中くらいの流れでは、サブエージェント `pr-check` に Issue の本文（「どうなるべきか」と、人間と決めたこと）を渡し、差分を確かめさせる。ずれは直し、直さないものは理由を PR の「レビューで見てほしいところ」に書く
10. PR を出す
    - タイトル：何をしたかの日本語1文
    - 本文：`.github/pull_request_template.md` に沿い、**`Closes #$ARGUMENTS`**。画面を撮り直したなら、撮り直した画像の一覧を「やったこと」に書く
11. CI の結果を `gh pr checks --watch --fail-fast` で、終わるまで待って確かめる（PR を出した直後は、まだ動いているため）。失敗していたら直してから次へ進む
12. PR の URL と、何をしたか（バグなら原因）を短く伝える

**マージはしない。**
