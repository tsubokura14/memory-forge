# 画面のプロトタイプ

見た目や操作の手触りは、言葉だけでは人間とAIの理解がずれやすい。そこで、本番を作る前に、触れる形で合意する。
プロトタイプは **合意するための道具で、本番のコードの手本にはしない**。

## 作るもの・作らないもの

| 作る | 作らない（仕様ファイルの文章だけで決める） |
| --- | --- |
| レイアウト、色、余白、文字 | データの保存、API、認証 |
| 状態ごとの表示（0件、大量、読み込み中、エラー、権限なし） | 入力チェックの中身。エラーの **見た目** だけを、決まった状態として作る |
| 画面のつながり（どのボタンでどこへ行くか） | 計算、並べ替え、検索の中身 |
| 操作の手触り（開閉、確認ダイアログ、エラーの出方） | 本物のデータ。表示用の決まったデータをページに書く |

## 作るかどうか

| 作る | 作らない |
| --- | --- |
| 新しい画面 | 文言だけの変更 |
| 画面の流れやレイアウトが変わる | 今ある見せ方の範囲で、項目を足す・減らす |
| `docs/ui.md` にない見せ方や部品が要る | 内部処理だけの変更 |
| 操作の手触りを言葉で決めにくい | バグ修正 |

## 技術

- HTML＋Tailwind CSS。開閉などの動きが要るところだけ Alpine.js を使う
- ビルドは Tailwind の CLI だけ。ビルド結果の CSS もコミットし、ファイルをブラウザで開けば見られるようにする（サーバーやバックエンドは作らない）
- 色・余白・文字は、トークン（`tokens.css`）にあるものだけを使う。`p-[13px]` や `#3366ff` のような、トークンにない値は使わない
- 状態は URL の `?state=empty` などで切り替える。`index.html` に、画面と状態の一覧を置く
- スクリーンショットは Playwright で、画面と状態の組み合わせごとに撮る
- 本番がどの技術でも、プロトタイプは HTML のままにする。部品の分け方や状態の持ち方がないので、本番がまねる材料にならないため

## 置き場所と、本番に見せない仕組み

本番を作るAIには、プロトタイプのソースを見せない。見せるのは仕様ファイル、スクリーンショット、`docs/ui.md`、トークンだけ。
見えたものには引っ張られるので、ルールで禁じるより、見えない場所に置く。

- プロトタイプは、**このリポジトリの外の別フォルダ** に、別の Git リポジトリとして置く。場所は人間が決める。チームで見るなら、GitHub に別のリポジトリを作る
  - 本番の作業では作業ディレクトリの外なので、検索に出てこない。読もうとしても、ツールでもコマンドでも、フック（`.claude/hooks/guard.mjs`）が止める
- `/dev-proto` の会話でだけ、`/add-dir <プロトタイプのフォルダ>` で作業ディレクトリに加える。その会話だけにして、設定には保存しない
- `/dev-proto` が終わったら会話を区切る。同じ会話のまま本番を作ると、AIが直前に書いたプロトタイプの作りをまねるため
- トークンは、本番のトークンファイルからプロトタイプへ、一方向にだけコピーする（立ち上げの手順3〜4だけは、プロトタイプで決めたものを本番に移す）

## 合意したものの残し方

| もの | 場所 |
| --- | --- |
| 合意した画面のスクリーンショット | `docs/changes/<年-月-日>-<何をするか>/<画面>-<状態>.png`。仕様PRで取り込む |
| 今の画面のスクリーンショット | `docs/specs/screens/<画面>-<状態>.png`。AIが本番の画面から撮る（`docs/process/screenshots.md`） |
| 決まった動き・文言 | 仕様ファイル（仕上げたら `docs/specs/`） |
| 見た目の決まり | 仕様ファイルの「画面」（仕上げたら `docs/ui.md`） |

- プロトタイプは、消えても困らない状態にしておく。決めたことは必ず上のどこかに書く
- プロトタイプは画面が変わるときだけ直すので、本番より古くなることがある。`/dev-proto` は最初に `docs/specs/screens/` と見比べ、プロトタイプを今の本番に合わせてから変える

## 本番を作るときの決まり

- 見た目はスクリーンショットと `docs/ui.md` に合わせる。部品は今ある本番の部品を使い、値はトークンを使う
- データの形や作りは、仕様ファイルの「設計」で決める。スクリーンショットに写っている項目名や並びから決めない
- 仕様に書いていないものは、スクリーンショットに写っていても作らない。仕様とスクリーンショットが食い違ったら、止めて質問する
