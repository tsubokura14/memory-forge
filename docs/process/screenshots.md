# 本番の画面を撮る

本番の画面は、AIが Playwright で撮る。人間は撮らない。撮った画像は、次の2つに使う。

- `docs/specs/screens/` の「今の画面」。本番から撮るので、いつも本番と同じになる
- 画像を比べるテストの基準。画面を変えるつもりのない変更で見た目が変わったら、テストが失敗する

## 仕組み（立ち上げの手順4でAIが作る）

- 画面と状態の組み合わせごとに `<画面>-<状態>.png` を撮る。撮る状態は、`docs/specs/` の画面の表にある状態
- 状態（0件、エラー、読み込み中など）は、テスト用のデータで作る。作り方は技術で決まるので、`docs/design.md` に書く
  - 画面がブラウザ側でデータを取ってくる作り：通信の返事を差し替える（Playwright の `page.route`）
  - サーバー側で画面を組み立てる作り：テスト用のデータベースに、決まったデータを入れる
- ログインが要る画面は、テスト用のユーザーでログインして撮る
- 撮るたびに変わるもの（今日の日付、アニメーション）は止める。日時は固定する
- 撮る環境は、**Playwright 公式の Docker イメージ**（入れた Playwright と同じバージョン）にする。手元で撮り直すときも、CI で比べるときも、同じイメージで動かす。OS が違うと文字の描き方が変わり、同じ画面でも画像が一致しないため（Windows で撮った画像は、Linux の CI と一致しない）。手元では Docker Desktop が要る
- 基準の画像の場所を `docs/specs/screens/` にする。Playwright はふだん、テストの横のフォルダに、OS 名の入った名前で基準の画像を置くので、置き場所と名前を変える設定が要る（`snapshotPathTemplate` など。設定の名前は、入れたバージョンのドキュメントで確かめる）。撮る環境は1つなので、名前に OS 名を入れない
- 撮り直すコマンドと、比べるテストのコマンドを、`CLAUDE.md` の「よく使うコマンド」に書く

## 撮り直すとき

| 場面 | AIがすること |
| --- | --- |
| 画面のタスク（`/dev-impl`） | **タスクに書かれた画面だけ** を、撮る状態を足して撮り直す。画像を開いて、合意したスクリーンショットと見比べる。違いは直し、直せないものは PR に書く。ほかの画面の比べるテストが失敗したら、撮り直さずに止まって伝える |
| 画面を変えるつもりのない変更 | 比べるテストが失敗したら、撮り直さずに止まって伝える |
| 小さな変更・バグ修正（`/dev-fix`） | 変えた画面だけを撮り直す |

- 撮り直す範囲を絞るのは、AIが意図しない変化まで撮り直して、比べるテストを通してしまわないようにするため
- 撮り直した画像は、その変更と同じ PR に入れ、一覧を PR 本文に書く。人間は、PR の画像の差分と、一覧がタスクの画面と合っているかを見る
- 機能の途中では、`docs/specs/screens/` の画像が、`docs/specs/` の文章より先に新しくなる。文章は仕上げPRで追いつく。画像を仕上げまで別の場所に置くと、比べるテストの基準が2か所に分かれるため、タスクPRで更新する
- プロトタイプと本番は作りが違うので、細かい差は残る。見比べるのは、合意したレイアウト・色・文言・状態ごとの表示が合っているか
