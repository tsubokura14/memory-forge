# 流れの選び方（`/dev-triage`）

Issue に取りかかる前に、どの流れで進めるかを決める。**変更の大きさではなく、うまくいかなかったときの影響で決める。** 1行の変更でも、データや権限に触るなら重い流れにする。

| 流れ | 当てはまる変更 | 進め方 |
| --- | --- | --- |
| **軽い**（`flow:light`） | 動きもデータも変わらない。文言・誤字、トークンの中での見た目の調整、文書、動きを変えない整理 | `/dev-fix`。仕様ファイルなし。新しいテストと pr-check は省く |
| **中くらい**（`flow:medium`） | 1か所の動きが変わり、「どうなるべきか」を Issue に1〜2文で書ける。ふつうのバグ修正 | `/dev-fix`。仕様ファイルなし。テストを先に書く。pr-check を使う |
| **重い**（`flow:heavy`） | 新しい画面や機能。受け入れ条件が3つ以上になりそうなもの。下の「必ず重い流れにするもの」に1つでも当たるもの | `/dev-spec` から（`/dev-spec` → 画面が変わるなら `/dev-proto` → `/dev-plan` → `/dev-impl` → `/dev-finish`） |

## 必ず重い流れにするもの

変更が小さくても、次に当たれば重い流れにする。

- データの形や保存の仕方が変わる（今あるデータの移し替えが要るもの）
- ログイン・権限・お金・個人情報に関わる
- 削除など、取り消せない操作に関わる
- 複数の画面で使う部品や、トークンの値を変える
- 外部のサービスとのつなぎ方を変える
- `docs/design.md` の決まりを変える・足す

## 決め方

- AIが、`/dev-triage` で理由つきの案を出す。**決めるのは人間。** 決めたら、AIが Issue に流れのラベルを付ける
- AIは、作業の途中で流れを重くする方向に気づいたら止まって伝える。軽くする方向には、自分で変えない
- どの流れでも省かないもの：main に直接入れない、CI を通す、画像を比べるテストを通す（画面を変えたら、変えた画面だけを撮り直す）
- 軽い・中くらいの境目（受け入れ条件の数など）は、実際の Issue で回しながら直す。迷ったら重いほうにする
