# 問題のファイルの作り方

Memory Forge で解く問題は、このリポジトリの中で Claude Code に作らせ、アプリの「取り込み」の画面から取り込みます。
ここでは、問題のファイルの形、作業場所のフォルダ、Claude Code のスキルと確かめるスクリプトの使い方、取り込むまでの流れを説明します。

## 問題のファイル

1つのファイルは、1つの Subject（科目）の問題を書いた JSON です。

````json
{
  "subject": "Python",
  "questions": [
    {
      "id": "k3f9a2",
      "topic": "Decorators",
      "type": "single",
      "text": "次のコードを実行したとき、出力されるものはどれか。\n\n```python\nprint(len([1, 2, 3]))\n```",
      "choices": ["2", "3", "4", "エラー"],
      "correct": ["B"],
      "explanation": "`len` はリストの要素の数を返すので、3 が出力されます。"
    }
  ]
}
````

- `type` は `single`（1つを選ぶ）か `multiple`（すべて選ぶ）。`correct` は、選択肢の並び順の記号（A・B・C…）で書きます
- 問題文・選択肢・解説の中のコードは ```` ``` ```` で囲み、言語の名前を付けると、アプリで色付きで表示されます。文の中の短いコードは `` ` `` で囲みます
- 書ける書き方は、項目によって違います
  - 問題文・選択肢：文の中のコード（`` ` ``）とコードブロック（```` ``` ````）だけです。ほかの書き方（`**`・`#`・`-` など）は、書いたままの文字で表示されます
  - 解説：Markdown のすべての書き方が使えます。強調（`**太字**`）・リスト・表・引用・コールアウト（`> [!tip]` など）・数式（`$…$`）・リンクなど。```` ```mermaid ```` は図にならず、コードブロックのまま表示されます。コードの外に `$`・`*`・`|` を書くと、数式・強調・表として表示されることがあります
- `id` は、同じ Subject の中で問題を見分けるためのものです。同じ Subject で同じ ID の問題を取り込むと、今ある問題が置き換わります。ID は手で考えず、下の「ID を付けるスクリプト」で付けます

項目の全部と、取り込むときに確かめること（誤りになるもの）は、[取り込みの仕様](specs/import.md)の「問題のファイル」と「ファイルの確かめ」にあります。

## 作業場所のフォルダ

問題のファイルは、リポジトリの `questions/` に置きます。`questions/` の中のファイルは Git に入りません（作った問題は公開しないため）。

問題の元はアプリの中身です。`questions/` は作る・直すときの作業場所で、ここのファイルを消しても、アプリの問題は消えません。

## Claude Code のスキル（`/make-questions`）

### 新しく作る

Claude Code で、Subject・Topic・問題数と、どんな問題がほしいかを書いて頼みます。

```
/make-questions Python Decorators 10問。中級向けで、複数選択を3問入れて
```

- Subject・Topic・問題数のどれかが足りなければ、Claude Code が作る前に聞きます
- 資料（手元のファイルや URL）を渡すと、それをもとに作ります。渡さなければ、Claude の知っていることから作ります
- `questions/python-decorators.json` のように、Subject と Topic から名前を付けた新しいファイルに書きます。同じ名前のファイルがあれば上書きせず、`python-decorators-2.json` のようにします
- 書き終えたら、ID を付け、確かめるスクリプトで誤りがなくなるまで直し、ファイルの場所・問題数・Topic を伝えます
- 問題文・選択肢・解説は、言われなければ日本語で書きます

### 書き出したファイルを直す

アプリの「問題の管理」で書き出したファイル（「Python を書き出す」「Python の不備の印を書き出す」）を `questions/` に置き、直すところを頼みます。

```
questions/python.json の k3f9a2 の解説を直して
```

```
questions/python.json の問題を直して（不備の印を書き出したファイル）
```

- Claude Code は、ID と Subject を変えず、頼まれた問題だけを直します。直したら確かめるスクリプトを走らせ、問題ごとに何をどう直したかを伝えます
- 問題を足すように頼むと、足した問題にだけ ID を付けます

## 確かめるスクリプト

手で書き換えたファイルなども、取り込む前に確かめられます。

```
npm run questions:check -- questions/python.json
```

- ファイルは1つ以上指定できます
- 取り込みの画面と同じ決まりで確かめ、誤りは画面と同じ文言で、ID・項目・内容を1行ずつ出します

  ```
  python.json：1 件の不備があります。
    k3f9a2  correct  選択肢にありません（E）。
  ```

- そのうえで、`questions/` の中の同じ Subject のほかのファイルと ID が重なっていないかも確かめます。重なっていると「ほかのファイル（python.json）と ID が重なっています。」と出ます
- 誤りがなければ「python.json：誤りはありません（Python・10問）。」と出ます
- 誤りが1つでもあると、0 以外の終わりのコードで終わります

## ID を付けるスクリプト

```
npm run questions:ids -- questions/python-decorators.json
```

- ID が空（`""`）か、ない問題に、英小文字と数字の6文字の ID を付けて、ファイルに書き戻します。ID のある問題は変えません
- 付ける ID は、同じファイルと、`questions/` の中の同じ Subject のほかのファイルの ID と重なりません
- アプリに取り込み済みの問題の ID は見ません。`questions/` にない今の問題と重なっていないかは、取り込む前の確認の「置き換える」の数で確かめます

## 取り込むまでの流れ

1. `/make-questions` で `questions/` にファイルを作る（または、手で書いて `npm run questions:ids` と `npm run questions:check` を走らせる）
2. アプリの「問題の管理」→「取り込む」で、そのファイルを選ぶ
3. 取り込む前の確認で、新しい問題・置き換える問題・変わらない問題の数を見る。新しく作ったファイルなのに「置き換える」があれば、ID が今ある問題と重なっているので、やめる。置き換わる問題の `id` を `""` にして `npm run questions:ids` を走らせ直し、もう一度取り込む
4. 「すべて取り込む」を押す

直すときも、アプリの中身が元です。問題の管理で書き出したファイルを `questions/` に置いて直し、同じように取り込み直します。不備の印の付いた問題を置き換えると、印が消え、その問題の記録もリセットされます。
