# 見た目の決まり

## トークン

- トークンファイル：`src/styles/tokens.css`（Tailwind には `src/styles/globals.css` で登録する）
- コードでもプロトタイプでも、トークンにない値（`p-[13px]`、`#3366ff` など）を使わない

## 雰囲気

コードが主役の、エディタのような画面。ボタン・ラベル・数字は等幅の文字にし、1画面に情報を多めに並べる。
ライトモードは紙のように落ち着いた色、ダークモードはエディタのような暗い色にする。

## ライトモードとダークモード

- 設定画面で system / light / dark を選ぶ。最初は system（OS の設定に合わせる）。選んだ値は端末ごとに覚える
- 両方のモードで、同じ名前のトークンを使う（モードごとに値だけが変わる）。モードごとに別のトークンを書き分けない

## 色の使い分け

| トークン | 使う場面 |
| --- | --- |
| bg | 画面の地 |
| surface | ヘッダー、選択肢、解説の囲みなど、地の上に乗せる面 |
| surface-raised | surface の上で、押せるものに指を乗せたとき |
| border | 区切り線と枠 |
| text | 本文 |
| muted | 補足の文字（パンくず、問題番号、選ばれていない選択肢の記号など） |
| primary | 画面の主な操作（submit、next など）と、選んでいる選択肢・今の問題。主な操作のボタンは1画面に1つだけ |
| on-primary | primary の地の上の文字 |
| success / success-soft | 正解。soft は正解の選択肢や結果の帯の地 |
| danger / danger-soft | 不正解と、取り消せない操作。soft は不正解の選択肢や誤りの帯の地 |
| warning / warning-soft | 不備の印 |
| flame | 連続日数（炎、日数、答えた日の印）。不備の印の warning とは分ける |
| code-bg、code-text、code-line | コードブロックの地・文字・行番号 |
| code-keyword、code-string、code-function、code-builtin、code-decorator、code-comment | コードの色分け |

## 余白と並べ方

- 中身は1列。幅は、PC でも読みやすい幅で止め、画面の真ん中に置く
- 対応する画面の幅：PC が中心。スマホの幅（390px ほど）でも崩れないようにする
- 選択肢は、PC でもスマホでも1列で縦に並べる

## 文字

- 文字は2種類：sans（問題文・解説・見出しの文章）と、mono（コード、ボタン、ラベル、数字、パンくず）
  - 文の中のコードを、地の色だけでなく文字の形でも見分けられるように、文章とコードで書体を分ける
- sans と mono は同じ家族の書体（英字だけを持つ）にし、日本語の文字は、どちらも同じ日本語の書体で表示する
  - 画面の表記は英語だが、取り込む問題（問題文・選択肢・解説）には日本語が入るため
  - 日本語は等幅ではないので、コードの中の日本語（コメントなど）は縦にそろわない。英字だけのコードはそろう
- 大きさは xs・sm・base・lg の4段階。見出しは lg まで
- display は、解き終わりの結果の得点と、トップの連続日数だけに使う（ひと目でわかるように）
- 連続日数の数字だけは、太くて表情のある display の書体にする
  - 続けるのが楽しくなるように、ほかの数字と違う「ごほうび」の見た目にするため。数字しか出さないので、日本語の書体は要らない

## 部品の使い分け

- ボタン
  - 主な操作：primary の地。1画面に1つ
  - ほかの操作（skip など）：枠だけ
  - 不備の印（flag）：枠のない文字だけのボタン。指を乗せると warning の色
- 選択肢：枠のある行。左に A・B・C… の記号を枠で囲んで付ける。単一選択は丸い枠、複数選択は四角い枠にする。選んでいる行は primary の枠と地
  - 丸と四角を、ラジオボタンとチェックボックスの見分け方に合わせるため
- 答え合わせのあと：正解の選択肢は success、選んで間違えた選択肢は danger、ほかはふつうの表示のまま。選ばなかった正解には「missed」と添える。結果は、問題と選択肢の間に帯で出す
  - ほかの選択肢を薄くしないのは、答えたあとに選択肢のコードを見比べられるようにするため
- 問題と選択肢の区切り：問題（問題文とコード）は囲まずに地の上に置き、選択肢の前に「choose one」（単一選択）か「select all that apply」（複数選択）の見出しと線を置く
  - 問題を囲むと、枠で囲んだ選択肢と見た目が似て、見分けにくくなるため
- 選択肢の中のコードブロック：問題文のコードと同じ見た目で、行番号は付けない。スマホの幅では、記号を上の行に置き、コードを幅いっぱいに出す
- 記号（正解・不正解の印、不備の印、戻る・進む、一覧の行の先へ進む印、開閉の印など）：文字の記号（✓ ✗ ⚑ ← → › ▸ など）を使わず、Google の Material Symbols（Outlined）のアイコンを置く。色は文字と同じ色にする
  - 文字の記号は、書体に入っていないと別の書体で表示され、手書きのようなくだけた形になって、画面の雰囲気に合わないため
- ロゴ：アプリ名の左に、ハンマーを45度傾けたアイコン（Google の Material Symbols の hardware を傾けたもの）を、primary の色で置く
  - アプリ名の forge（鍛える）から。単純な形なので、上のバーの小さな大きさでもつぶれない
- 上のバー：アプリ名（ホームへ戻る）と sign out だけを置く。設定画面へは、ホームのメニューから行く。画面の行き来は、ホームのメニューと、各画面の左上の戻るリンクで行う。解く画面だけは、quit と進み具合を置く
- 下に固定した操作：解く画面と結果の画面は、主な操作のボタンを画面の下に固定し、幅いっぱいに大きく置く
  - スマホで、親指で押しやすくするため
- 答えたあと：問題と解説を1画面に並べず、下のボタン（explanation / question）で切り替える
- 選ぶもの：一覧から1つ選ぶもの（Topic）は、丸の付いた行。少しの中から1つ選ぶもの（順番、問題数）は、横に並べたボタンで、選んでいるものだけを surface の地にする
- プルダウン（Manage の Subject と Topic）：ブラウザの select は使わず、押すと下に選ぶものの一覧を開く。開いている間は枠を primary にし、右の印（expand_more）を上向きにする
  - 一覧の中の行：選んでいるものは primary-soft の地と primary の文字で、左に check の印。行の右に、不備の印の数（あれば warning）と問題数を等幅で出す。「All topics」は一番上に置き、ほかと区切り線で分ける
  - 数が多いときは、一覧の高さを止めて中をスクロールする
  - ブラウザの select では、開いたときの見た目を変えられず、問題数などを並べられないため
- 浮かせて重ねるもの（プルダウンの一覧、ダイアログ）：popover の影を付ける。ほかの部品には影を付けない
  - 下の一覧の上に重なっても、境目がわかるようにするため
- ページ（Manage の問題の一覧）：50問ずつ。絞り込みと一覧の間に、左に「151–200 of 480」、右に前後のボタンとページの番号を置く。番号は、最初・最後・今のページの前後だけを出し、間は「…」にする。今のページは primary の地。スマホの幅では番号を出さず、前後のボタンの間に「4 / 10」と出す。1ページで収まるときは、前後のボタンと番号を出さない
- 一覧：枠で囲んだ行を、区切り線で並べる。数（問題数、正答率など）は等幅で右にそろえる
- 今の身についている具合（Home の Subject、Setup の Topic）：細い線を、最後に正解した問題（success）・最後に間違えた問題（danger）・まだ解いていない問題（border）の割合で塗り分ける。線の下に「30 correct · 10 wrong · 8 new」と数を出し、右に % を出す。まだ1問も解いていなければ % は「—」
- 問題ごとの正答率（Manage）：等幅の数字（75% など）と解いた回数。まだ解いていないものは「—」
- 連続日数（Home のいちばん上）：menu などと同じく、枠の外の上に「day streak」の見出しを置く。枠の中は、PC でもスマホの幅でも、左に炎と日数、右に今週の7日の炎を1行に並べる。その下に区切り線を引き、今日の様子を出す
  - 炎と日数：今日答えたら塗りつぶしの炎と日数を flame の色で、まだなら線だけの炎を muted、日数を text で出す（「今日も灯す」と感じられるように）。0日は日数も muted
  - 今週の7日：日ごとに、左の炎と同じ形の炎を置く（毎日1つずつ灯していく感じを出すため）。答えた日は塗りつぶしの炎を flame、今日まだなら線だけの炎を flame でゆっくり点滅、答えなかった日は線だけの炎を border、これからの日は border の小さな点。下に曜日（Mon など。スマホの幅では M など1文字）を出し、今日の曜日は flame の色にして、その下に flame の小さな点を付ける。スマホの幅では、炎を小さくし、7つを詰めて右に寄せる
  - 今日の様子：答えた：success の「done today」、まだ：flame の「answer today to keep the flame」、0日：muted
- 解き終わりの結果：上に「session complete」と Subject の名前。その下の枠の真ん中に、正答率の円（success の線、真ん中に % と accuracy）と得点（6/9、display）を横に並べる。枠の下に、correct・incorrect・skipped・flagged（not counted）の数を小さなカード4枚で並べる（PC は横に4枚、スマホの幅では2行2列）
  - Topic ごとの行には、正解（success）と不正解（danger）の割合の線、得点（3/4）、% を並べる
  - 数える問題が0問（全部に不備の印）のときは、円を線だけにし、% と得点を muted の「—」、得点の下を「no questions counted」にする。Topic ごとの一覧は出さない
- 外のページ（GitHub のドキュメントなど）へのリンク：枠で囲んだ1行にし、左に内容を表す印（説明なら menu_book を primary の色で）、真ん中に題と短い説明、右に open_in_new の印を置く。別のタブで開く
  - アプリの中の画面へ移るリンクと見分けられるようにするため
- 取り消せない操作（削除）：ボタンは danger の文字。Subject と Topic の削除は、それぞれのプルダウンのすぐ右に、delete の印だけの枠のボタンを置く（指を乗せると danger）。Topic が「All topics」のときは、Topic の削除のボタンを出さない。押したら確認のダイアログを出し、消えるもの（問題数、記録）と、取り消せないことを書く
- 不備の印が付いているもの：warning の色で flag の印と数を出す。一覧の行は、warning-soft の地にする
  - Manage の問題の行には、flag の印と「unflag」を warning の文字のボタンで出し、押すと印が外れる
- 書き出しのボタン（Manage）：「export Python」のように Subject の名前を入れる。印の一覧を見ているときは「export flagged · Python」
  - 書き出しは Subject 単位なので、Topic で絞っていても、その Topic だけを書き出すように見せないため
- 取り込む前の確認：ファイル名 → Subject の名前を出す。まだない Subject のときは、success の枠で「new subject」と添える
- 中身の幅：ログインとパスワードの再設定は sm の幅のカードにする。ほかの画面は、どれも page の幅で止める
- コードブロック：code-bg の地に枠を付ける。問題文のコードには行番号を付ける
- 文の中のコード：code-bg の地で囲む
- 進み具合（解く画面）：上のバーの右に、ここまでの正解の数（success の check の印）、不正解の数（danger の close の印。スキップを含む）、今の問題の番号（4/10 など）を出す。上のバーの下の端に、答えた割合だけ伸びる primary の線を、画面の端から端まで引く（残りは border）
  - 問題数が多くても（ALL で100問以上など）同じ見た目で済むように、1問ずつの○×は並べない。1問ずつの結果は、解き終わりの結果の画面で見る

## 状態の見せ方

- 0件：点線の枠の中に、短い説明と、次にすることのボタン（あれば）を出す
- 読み込み中：出てくるものと同じ形の枠を、surface-raised の色で点滅させる
- 読み込みや保存のエラー：danger の帯で出し、右に retry のボタンを置く
- 取り込むファイルの誤り：danger の帯で「何件の誤りがあり、何も取り込んでいないこと」を出し、その下に、問題・項目・内容を1行ずつ並べる
- 終わったこと（取り込めたなど）：success の帯や枠で出す

## 文言

- 画面の表記は英語（`docs/overview.md` の「用語」）
- ボタンとラベルは小文字で短く（submit、skip、flag、next など）。問題文と解説は、ふつうの文の書き方のまま
- 問題文・選択肢・解説は、取り込んだデータの言葉のまま出す（日本語のことも英語のこともある）
