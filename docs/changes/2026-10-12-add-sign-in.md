# ログインできる（#3）

## なぜ

PC とスマホで同じ問題と記録を使い、公開しても他人に問題や記録を見られないようにするため。使うのは自分ひとりなので、自分のメールアドレスとパスワードだけが通り、新しい登録はできないようにする。

## 影響する今の仕様

- `docs/specs/home.md`：仮の最初の画面（`/`）。ログインしていないと見られなくなり、上のバーが付く
- 新規：`docs/specs/sign-in.md`（Login と、ログインしていないときの扱い）
- 新規：上のバー（どの仕様ファイルに書くかは「決まっていないこと」）

## 使う場面

1. 自分のアカウントを持つ人が、スマホのブラウザでアプリの URL を開くと、Login が出る。メールアドレスとパスワードを入れて sign in を押すと、Home が出る
2. 同じ人が、パスワードを打ち間違えて sign in を押すと、Login のまま、入れなかったことを伝える帯が出る。メールアドレスは消えずに残る
3. 他人がアプリの URL を開いても、Login しか見られない。自分のメールアドレスを知らなければ入れず、登録する手段もない
4. ログインしている人が、Home の上のバーの sign out を押すと、Login に戻る。ブラウザの戻るで前の画面に戻っても、中身は見られない

## 受け入れ条件

- ログインしていない人が、Login 以外のどの画面を開いても、Login が出る
- Login で、登録されたメールアドレスと正しいパスワードを入れて sign in を押すと、Home が出る
- メールアドレスかパスワードが違うと、Login のまま、danger の帯でエラーを出す。どちらが違ったかは出さない
- Login の forgot password? を押すと、パスワードの再設定の画面（#4）へ移る
- Login に、新しく登録する手段はない
- ログインしている人が Login を開くと、Home が出る
- 上のバーは、解く画面以外のログイン後のすべての画面に出る。アプリ名（memory-forge）を押すと Home、sign out を押すと Login に移る
- sign out したあとは、ログインしていない人と同じ扱いになる（戻るで前の画面に戻っても、中身は見られない）

## やらないこと

- 新しい登録、自分以外の人のログイン（`docs/overview.md` の「やらないこと」）
- パスワードの再設定（#4）。この Issue では、forgot password? のリンクを置くところまで
- Google でのログイン（#14）
- アプリの画面から、パスワードやメールアドレスを変える
- Home の中身（連続日数など）。この Issue では、今の仮の画面に上のバーを付けるだけ

## 決まっていないこと

- [ ] 自分のアカウント（メールアドレスとパスワード）は、どうやって最初に作る？ アプリの画面には登録の手段がないので、画面の外で作る前提でよいか
- [ ] forgot password? の行き先の Reset（#4）はまだない。この Issue では、リンクを置かない／押しても何も起きない／仮の画面に移る、のどれにするか
- [ ] ログインしていない人が、Home 以外の画面（たとえばあとでできる Manage）を開いて Login に戻されたとき、sign in のあとは Home に行くか、開こうとしていた画面に行くか
- [ ] ログインしたままでいられる長さは？（例：ブラウザを閉じても30日は入ったまま、など）
- [ ] パスワードを何度も間違えたとき、しばらく入れなくする？ するなら、何回で、どのくらいの間か
- [ ] エラーの帯の文言は？（例：「incorrect email or password」）
- [ ] つながらないなど、サーバーのエラーのときの表示は？ `docs/ui.md` の「読み込みや保存のエラー」には retry のボタンがあるが、Login でも retry を出すか、帯だけにするか
- [ ] メールアドレスやパスワードが空のまま sign in を押したら？（押せないようにする／押したら帯を出す）
- [ ] 送っている間は、ボタンを押せなくして文言を変える？（例：「signing in…」）
- [ ] Login の画面に、アプリ名やロゴは出す？ 上のバーは出す？
- [ ] 入力欄のラベルの文言は？（例：email、password）
- [ ] 上のバーは、どの仕様ファイルに書くか（Login と同じ `sign-in.md`、または新しく `app-bar.md` など）
