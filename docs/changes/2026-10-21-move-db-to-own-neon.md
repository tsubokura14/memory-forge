# 本番と Preview のデータベースを、自分の Neon のアカウントにまとめる（#35）

## なぜ

本番（main）と確かめ用の公開（Preview）のデータベースは、Vercel が作った Neon の組織にある。手元の開発・テスト・CI（`dev`・`test`・`ci`）は、自分の Neon のアカウントにある。管理する場所が2つに分かれていて不便。#34 の Preview の公開では、Vercel が作った組織の Neon のブランチの数が上限に当たった。

本番のデータは、自分のアカウント1つだけでほとんどない。移すなら今がいちばん楽なので、今のうちに1か所にまとめる。

## 影響する今の仕様

- `docs/specs/` の動きは変わらない（画面もログインの動きも同じ）
- 変わるのは、データベースがどこにあるか（`docs/design.md` の「データベースのつながり方」）

## 使う場面

1. 自分が、自分の Neon のアカウントを開くと、本番・Preview・`dev`・`test`・`ci` のブランチがすべて同じ1か所に並んでいる
2. 自分が、作り直した自分のアカウントで本番の URL から sign in すると、Home が出る
3. 自分が PR を出すと Preview が公開され、そこでも本番と同じアカウントで sign in できる。PR をマージして Git のブランチを消すと、次の Preview の公開のときに、その Preview の分のブランチが消える

## 受け入れ条件

- 本番・Preview・手元の開発・手元のテスト・CI のデータベースが、すべて自分の Neon のアカウントの同じプロジェクトにある
- 本番の URL で、作り直した自分のアカウントで sign in でき、Home が出る
- PR を出すと Preview が公開され、Login が出る。本番と同じアカウントで sign in できる
- PR をマージすると、その Git のブランチが自動で消える
- Git のブランチを消すと、その Preview の分のブランチが、次の Preview の公開のときに消える
- 本番に使う main には、移したあとに作り直したアカウントのほかのデータが入っていない
- Neon のブランチは、main・`dev`・`test`・`ci` と、Preview の分だけ（Vercel の Development 用のブランチは作らない）
- 手元の開発・手元のテスト・CI は、移す前と同じように動く
- 本番で動くことを確かめたあと、Vercel が作った Neon の組織が消えている

## 画面

画面は変わらない。

## やらないこと

- 今の本番のデータ（アカウント、ログインの状態、間違えた回数）を、新しいほうへ写さない。アカウントは `npm run user:create` で作り直す
- アプリのコード・画面・ログインの動きは変えない
- データベースの接続先の証明書の確かめ方（`sslmode`）は変えない（#38 で扱う）
- Neon の有料のプランにしない
- 切り替えている間に本番が使えない時間（数分〜数十分）を、なくす工夫はしない（使う人が自分ひとりのため）
- Preview を同時に6本より多く置けるようにはしない（1タスク = 1PR で順に進めるので、同時に7つ以上の PR は出さない）

## 調べたこと

Neon の公式ドキュメント（2026-10-21 に確かめた）

- Neon が管理する Vercel 連携（https://neon.com/docs/guides/neon-managed-vercel-integration）
  - Vercel の Marketplace から、今ある自分の Neon のアカウントをつなぐ形で入れられる。Vercel のプロジェクトに、Neon のプロジェクト・データベース・ロールを選んでつなぐ
  - Preview の公開ごとに `preview/<Git のブランチ名>` のブランチを作り、その公開だけに接続先を入れる（今と同じ）
  - 「Automatically delete obsolete Neon branches」：Git のブランチが消えたら、その Preview のブランチを消す。消すのは、次に Preview が公開されるとき
  - 入れる接続先は `DATABASE_URL`（接続プールを通す）と `DATABASE_URL_UNPOOLED`（通さない）。今のコードが読む名前と同じ
  - 本番がどのブランチを使うかは、ページに書かれていない。プロジェクトのいちばん上のブランチ（main）になると考えているが、設計のときにもう一度確かめる
- プラン（https://neon.com/docs/introduction/plans）：無料のプランは、1つのプロジェクトにブランチ10本まで。超えるには、消すか有料にする
